# CURSOR RULES — Single Source of Truth (SSOT) for KEIS site

Этот репозиторий живёт по принципу: **для каждого блока — одна правда**.
Никаких дублей, “перебиваний внизу файла”, вторых наборов media и альтернативных имён.

---

## 0) Миссия и критерий приёмки
Ты работаешь как ведущий инженер/архитектор/разработчик/дизайнер.
**Результат считается готовым ТОЛЬКО если:**
- нет ошибок CSS/JS/HTML (lint/парсер/IDE Problems = 0 критических),
- блок/правка работает на нужных брейкпоинтах,
- по блоку нет дублей/алиасов/вторых жизней,
- ты сделал самопроверку и приложил краткий отчёт + команды проверки.

---

## 1) Абсолютные запреты (NO GO)
1) ❌ Нельзя “чинить” добавлением новых правил в конец файла, чтобы перебить старые.
2) ❌ Нельзя создавать второй набор правил/медиа для того же блока ниже по файлу.
3) ❌ Нельзя плодить новые имена классов, если задача не просит миграцию/рефакторинг.
4) ❌ Нельзя использовать !important как “лекарство”, кроме строго согласованных случаев.
5) ❌ Нельзя трогать лишние файлы/страницы/блоки — только то, что в задаче.

---

## 2) Как править любой блок (строго)
### Шаги
1) Найди блок по селекторам в `styles.css` и по HTML (rg/search).
2) Собери ВСЕ упоминания/дубли этого блока по файлу и по репо:
   - `rg -n "selector|alias|oldname" -S .`
3) Оставь **ОДИН канонический блок** (SSOT), остальное удали/слий.
4) Приведи структуру блока к единому шаблону (см. раздел 3).
5) Убери старые алиасы/необычные имена, которые конфликтуют.
6) Сделай самопроверку (см. раздел 6) и только потом сдавай.

---

## 3) Стандарт оформления блока в CSS (обязательно)
Каждый блок начинается так:

/* =========================
   BLOCK: <NAME>
   SSOT: single source of truth
   ========================= */

Внутри блока порядок ВСЕГДА такой:
(A) base (без media)
(B) mobile:  @media (max-width: 768px)
(C) tablet:  @media (min-width: 769px) and (max-width: 980px)
(D) desktop: @media (min-width: 981px)
(E) large:   @media (min-width: 1200px) / 1500px (если нужно)

Правило:
- **никаких других media для этого блока ниже по файлу**
- если есть второй набор — слить в этот набор и удалить дубликат

---

## 4) Правила по именам и “вторым жизням”
- У блока должен быть один неймспейс (пример: `.kf-flags` или `.kgx-b4`).
- Любые старые имена (`old-*`, `*_legacy`, `*_v2`, случайные алиасы) должны быть:
  - удалены, или
  - сведены к одному источнику (но лучше удалить).
- Если нужна миграция имён — сначала план, потом массовая замена по репо, потом проверка 0 вхождений.

---

## 5) Правила по адаптиву (чтобы не “вылезало”)
- На desktop элементы не должны выходить за свой контейнер:
  - max-width/inline-size ограничиваем,
  - используем clamp(),
  - учитываем padding контейнера.
- Если есть фон/маска (рваные листы) — карточки обязаны жить внутри безопасной зоны:
  - вводим переменные safe inset (например `--kf-safe-left/right`),
  - ширина карточек считается от доступной ширины колонки минус safe inset,
  - при уменьшении экрана карточки уменьшаются пропорционально.

---

## 6) Обязательная самопроверка перед сдачей
### Минимальный чек-лист (выполнить и отчитаться)
1) CSS парсится без ошибок:
   - Problems в IDE: 0 critical
2) По блоку нет дублей:
   - `rg -n "<block-selector>" styles.css` → один канонический блок
3) Нет старых имён:
   - `rg -n "oldname1|oldname2|alias" -S .` → 0
4) Визуальная проверка на брейкпоинтах:
   - 390, 768, 980, 981, 1200, 1440
5) Сдать краткий отчёт:
   - что удалено,
   - что стало каноном,
   - какие команды проверки,
   - какие файлы реально изменены.

---

## 7) Формат отчёта в конце работы (обязателен)
- ✅ Что сделано (3–7 пунктов)
- ✅ Где канон (точный диапазон строк / маркер)
- ✅ Что удалено (список алиасов/дублей)
- ✅ Команды проверки
- ✅ Статус: PASS (100%) / FAIL (и что осталось)

---

## 8) Важное правило: правим только задачу
Если задача про один блок — НЕ ТРОГАТЬ другие блоки.
Если видишь проблему рядом — отметь в отчёте как “наружное наблюдение”, но не правь.
